# 關鍵程式碼與重要觀念

這份文件挑出四個最值得向教授解釋的程式片段；完整實作請見 `rtl/`、`sim/`、`firmware/`。

## 1. Shift 查表：雙曲 CORDIC 的重複迭代

在 `rtl/ln/cordic_ln_parallel_10ch.sv` 與 `rtl/exp/cordic_exp_parallel_10ch.sv` 中，迭代順序是：

```systemverilog
0: shift_for = 1;
1: shift_for = 2;
2: shift_for = 3;
3: shift_for = 4;
4: shift_for = 4;  // repeated
// ...
13: shift_for = 13;
14: shift_for = 13; // repeated
15: shift_for = 14;
```

這裡顯示的是 exp 核心的 `shift_for` 函數；ln 程式中對應名稱為 `stage_shift`。用固定次數的移位取代一般乘法，正是 CORDIC 適合 RTL 的關鍵。

## 2. exp：根據 Z 方向旋轉

節錄自 `rtl/exp/cordic_exp_parallel_10ch.sv`：

```systemverilog
if (z[k] >= 0) begin
    xn[k] = x[k] + (y[k] >>> shift_amt);
    yn[k] = y[k] + (x[k] >>> shift_amt);
    zn[k] = z[k] - angle;
end else begin
    xn[k] = x[k] - (y[k] >>> shift_amt);
    yn[k] = y[k] - (x[k] >>> shift_amt);
    zn[k] = z[k] + angle;
end
```

一個通道各有 X、Y、Z；十通道透過 `for (k = 0; k < 10; k++)` 同時更新。`>>>` 是**算術右移**，可保留有號定點數的符號。

## 3. MMIO：CPU 寫 START 並讀取結果

exp 及 ln 的 MMIO 皆採同一批次操作形式，來自 [`rtl/exp/cordic_exp_parallel_10ch_mmio.sv`](../rtl/exp/cordic_exp_parallel_10ch_mmio.sv)：

```systemverilog
else if ((bus_addr >= BASE) && (offset == 32'h80)) begin
    if (bus_write && (bus_wdata == 32'd1) && !busy && !start_pulse)
        start_pulse <= 1'b1;
    else
        bus_error <= 1'b1;
end
```

CPU 向 `BASE + 0x80` 寫入 1。MMIO 將 `start_pulse` 拉高一個週期後由 ten-channel core 接收。同時提供 STATUS、INVALID、RESULT 與 bus response handshake。此介面是模擬用的簡化 CPU-like bus，不是經正式驗證的 AXI/APB 硬體 IP。

## 4. SoftConsole C：CPU 操作的流程

參考 `firmware/ln10_reference.c` 或 `firmware/exp10_reference.c`：

```c
for (uint32_t ch = 0; ch < 10; ch++)
    REG32(INPUT_BASE + 4u*ch) = (uint32_t)inputs[ch];
REG32(CMD_START) = 1u;

for (uint32_t tries = 0; tries < 1000; tries++) {
    if ((REG32(STATUS) & 1u) != 0u) break;
}

for (uint32_t ch = 0; ch < 10; ch++)
    REG32(RAM_RESULT + 4u*ch) = REG32(RESULT_BASE + 4u*ch);
```

CPU 透過 volatile 記憶體讀寫對外設傳送指令，不能讓編譯器將這些存取最佳化成一般變數操作。正式完整範例還有逾時、INVALID、結果精度與 RAM 旗標檢查。

**備註：** 此處 C 程式為依實驗流程重整理的 reference，不保證產生與已驗證 HEX 逐位元相同的程式。若要做到完全可重製編譯，應將原始 SoftConsole `mivuse.c`、`linker.ld` 與 build 設定一併加入。

## 5. 單通道公平對照組

`rtl/single_serial/cordic_ln_1ch_mmio.sv` 與 `cordic_exp_1ch_mmio.sv` 中可找到排程狀態：`S_IDLE`、`S_FIRE`、`S_WAIT_BUSY`、`S_WAIT_DONE`。每完成一筆，就將單核心的結果放到對應通道暫存器，接著索引加一，再進行下一筆；第十筆完成才拉高整批的 DONE。

因此 CPU 看到的 MMIO 暫存器與 10CH 相同，不需要改成「軟體發送十次 START」。
